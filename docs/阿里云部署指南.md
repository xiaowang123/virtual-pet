# 云宠物 CloudPet 部署到阿里云 · 完整指南

本指南提供 3 种部署方式, 从省心到省钱依次是:

| 方案 | 适合 | 月成本 | 步骤 |
|---|---|---|---|
| **A. 轻量应用服务器 / ECS + Docker** (推荐) | 长期稳定运行、要绑域名 | ¥24 起 | 见下文 |
| **B. 函数计算 FC(自定义容器)** | 个人玩、想几乎不花钱 | 几乎为 0(按调用计费) | [跳到方案 B](#方案-b函数计算-fc自定义容器) |
| **C. SAE 应用引擎** | 企业级免运维 | 较高 | [跳到方案 C](#方案-csae-serverless-应用引擎) |

> 三套方案共用同一个 Docker 镜像, 游戏数据都存在容器挂载卷里(单实例)。若要多实例水平扩展, 把 `src/store.js` 的 JSON 存储换成云数据库 RDS MySQL 即可。

---

## 准备: 构建并上传镜像到 ACR(三套方案都要做)

1. **开通容器镜像服务 ACR**(个人版免费): 登录阿里云控制台 → 搜索「容器镜像服务」→ 创建个人版实例 → 记下实例地址, 形如 `registry.cn-hangzhou.aliyuncs.com`。
2. 进入实例 → 命名空间 → 创建命名空间, 例如 `pet`。
3. 进入实例 → 访问凭证 → 设置固定密码(或直接用阿里云账号密码), 记下 **用户名 + 密码**。
4. 本地(或 ECS 上)登录并推送:

```bash
docker login registry.cn-hangzhou.aliyuncs.com   # 输入上一步的用户名密码
docker build -t registry.cn-hangzhou.aliyuncs.com/pet/cloud-pet:latest .
docker push registry.cn-hangzhou.aliyuncs.com/pet/cloud-pet:latest
```

> 或者把仓库推到 GitHub, 用项目里自带的 [GitHub Actions](../.github/workflows/aliyun-acr.yml)
> 自动构建推送: 在仓库 Settings → Secrets 里填 `ALIYUN_ACR_REGISTRY / ALIYUN_ACR_NAMESPACE / ALIYUN_ACR_USERNAME / ALIYUN_ACR_PASSWORD` 四个变量, 每次 push 到 main 自动出新镜像。

## 方案 A: 轻量应用服务器 / ECS + Docker(推荐)

1. **购买服务器**: 控制台搜索「轻量应用服务器」→ 创建服务器 → 地域选离你近的(如华东1杭州)→ 镜像选 **Ubuntu 22.04 / CentOS 7.9 / Alibaba Cloud Linux 3**(最省事的是直接选带 Docker 的应用镜像)→ 套餐 2核2G(¥24~60/月)即可。
2. **放行端口**: 服务器详情页 → 防火墙(轻量)/安全组(ECS)→ 添加规则放行 **22**(SSH)、**80**(HTTP)、**443**(HTTPS)。ECS 用户还需要在安全组里放行。
3. **SSH 登录服务器**, 安装 Docker(若镜像已带可跳过):

**Ubuntu / Debian:**

```bash
sudo apt update && sudo apt install -y docker.io
sudo systemctl enable --now docker
```

**CentOS 7 / CentOS 8 / Alibaba Cloud Linux:**

```bash
# 用阿里云镜像源安装 Docker CE
sudo yum install -y yum-utils
sudo yum-config-manager --add-repo https://mirrors.aliyun.com/docker-ce/linux/centos/docker-ce.repo
sudo yum install -y docker-ce docker-ce-cli containerd.io
sudo systemctl enable --now docker
```

> CentOS 7 已停止维护, 官方源里只保留到 Docker 23.0.x。如果上面安装报「没有可用软件包」, 固定装老版本:
> `sudo yum install -y docker-ce-23.0.6 docker-ce-cli-23.0.6 containerd.io`。实在不行就换个 Alibaba Cloud Linux 3 镜像重装系统(控制台一键更换, 几分钟)。

4. **关掉系统自带的 firewalld**(CentOS 特有, 这是最常见的"部署完访问不了"的原因): 轻量控制台的防火墙已经做了端口过滤, 系统里的 firewalld 再挡一层, 导致 80 端口进不来。二选一:
   - 放行端口: `sudo firewall-cmd --permanent --add-port=80/tcp --add-port=443/tcp && sudo firewall-cmd --reload`
   - 或直接关闭: `sudo systemctl stop firewalld && sudo systemctl disable firewalld`
5. **登录 ACR 并启动容器**:

```bash
sudo docker login registry.cn-hangzhou.aliyuncs.com
sudo docker pull registry.cn-hangzhou.aliyuncs.com/pet/cloud-pet:latest
sudo docker run -d --name cloud-pet \
  -p 80:3000 \
  -v pet-data:/app/data \
  --restart unless-stopped \
  registry.cn-hangzhou.aliyuncs.com/pet/cloud-pet:latest
```

6. **访问**: 浏览器打开 `http://<服务器公网IP>` 就能领养宠物了 🎉 打不开的话依次排查: `curl http://127.0.0.1:3000/healthz`(容器是否正常)→ `curl http://127.0.0.1/healthz`(端口映射)→ 控制台防火墙规则 → firewalld(第 4 步)。
7. **更新版本**: 本地推新镜像后, 在服务器上执行:

```bash
sudo docker pull registry.cn-hangzhou.aliyuncs.com/pet/cloud-pet:latest
sudo docker rm -f cloud-pet
# 重新执行第 5 步的 docker run (数据在 pet-data 卷里, 不会丢)
```

### 绑定域名 + HTTPS(可选但推荐)

1. 买个域名(阿里云「域名」产品, 几块钱起)。
2. **ICP 备案**(必须): 域名控制台 → 备案 → 阿里云免费代办, 一般 7~20 天。不备案无法用域名访问, 但**公网 IP 可以直接访问**(微信内打开则必须备案域名)。
3. 域名解析: 「云解析 DNS」→ 添加 A 记录 → 指向服务器公网 IP。
4. 证书: 「数字证书管理服务」→ 申请免费 DV 证书 → 签发后下载 nginx 证书。
5. 服务器上用 Caddy 自动 HTTPS(最省事):

**Ubuntu / Debian:**

```bash
sudo apt install -y caddy   # 或按 caddyserver.com 官方指引安装
sudo tee /etc/caddy/Caddyfile > /dev/null <<'EOF'
pet.example.com {
    reverse_proxy 127.0.0.1:3000
}
EOF
sudo systemctl restart caddy
```

**CentOS:**

```bash
sudo yum install -y yum-plugin-copr
sudo yum copr enable -y @caddy/caddy
sudo yum install -y caddy
sudo tee /etc/caddy/Caddyfile > /dev/null <<'EOF'
pet.example.com {
    reverse_proxy 127.0.0.1:3000
}
EOF
sudo systemctl enable --now caddy
```

## 方案 B: 函数计算 FC(自定义容器)

按请求计费, 没人玩时缩到 0 实例, 个人用几乎不花钱; 缺点是长时间没访问后首次打开有约 1~2 秒冷启动。

1. 控制台搜索「函数计算 FC」→ 开通(3.0 版)。
2. 左侧「应用」→ 创建应用 → 选择 **「通过自定义容器镜像创建应用」** → 镜像地址填 ACR 里的 `registry.cn-hangzhou.aliyuncs.com/pet/cloud-pet:latest`。
3. 配置:
   - 监听端口: **3000**(与镜像 EXPOSE 一致)
   - 内存 512MB、超时 120 秒即可
4. 创建后进应用详情 → **触发器** → 创建触发器:
   - 类型选 **HTTP 触发器** → 认证方式选「无需认证」
   - 创建后会得到一个公网 URL, 形如 `https://<id>.cn-hangzhou.fcapp.run`, 直接访问即可。
5. 域名: 在 FC「自定义域名」里绑定(需已备案), 证书同样用免费 DV。

## 方案 C: SAE(Serverless 应用引擎)

1. 控制台搜索「SAE」→ 开通 → 创建应用。
2. 来源选「镜像」→ 填 ACR 镜像地址 → 端口填 **3000**。
3. 实例数建议「按需弹性」, 最小 1 实例(SAE 缩到 0 需要开通高级功能)。
4. 创建完成后默认分配公网入口, 直接访问; 绑定域名与 HTTPS 在应用「网络设置」里配置。

## 常见问题

**Q: 数据存在哪? 重启会丢吗?**
数据在容器的 `/app/data/` 里(宠物档案 `pets.json` + 用户上传的自定义形象 `uploads/`), 上面所有方案都挂了持久卷(ECS 的 `pet-data` 卷 / FC 与 SAE 的 NAS), 重启不丢。备份: `sudo docker cp cloud-pet:/app/data ./backup`。

**Q: 朋友打开和我看到的是同一只宠物吗?**
是。宠物档案只存在服务器的 `pets.json` 里, 页面每次打开都全量拉取, 所以任何人、任何设备打开看到的都是同一群宠物, 也都可以投喂/改名/放生; 浏览器只记住"当前看的是哪只"(localStorage 的 `cloudpet.petId`), 这个偏好丢了没关系, 打开页面会自动选中一只 —— 换设备、清缓存、换浏览器都不会再出现"宠物不见了"。宠物 ID 见 `pets.json` 的 `pets` 字段, 也可用 `curl http://<地址>/api/pets` 查看全部。

**Q: 能接微信吗?**
可以。网页链接在微信内置浏览器直接可玩(需备案域名 + HTTPS)。做小程序需要企业主体账号, 后端 API 已按「一只宠物一个 ID」设计, 加微信登录换取 openid 绑定即可, 无需重构。
